# weewx-livedata

Writes the current WeeWX readings to `live.json` on your web host, every few
seconds.

A WeeWX service collects LOOP readings and sends signed HTTP posts to
`live.php`. The PHP endpoint writes the file beside your pages. Your page reads
that static file, so visitors do not trigger PHP execution or database queries.
The station only needs an outgoing connection.

Archive JSON is the job of WeeWX's JSON generator in 5.6. This extension handles
the live readings and works independently of it.

## Requirements

* WeeWX 5.2 or later, with Python 3.7 or later
* A web host running PHP over HTTPS, with write access to the directory holding
  `live.php`

## Installing

With a WeeWX build that includes extension repositories:

``` sh
weectl extension repo add livedata https://raw.githubusercontent.com/weewx-packages/weewx-livedata/master/repository.json
weectl extension install livedata
```

You can find the package with `weectl extension search php`. To check for and
install updates from this source:

``` sh
weectl extension check-updates livedata
weectl extension update livedata
```

For WeeWX versions without repository support, install the release archive:

``` sh
weectl extension install https://github.com/weewx-packages/weewx-livedata/releases/download/v0.2.0/weewx-livedata-0.2.0.zip
```

The installer registers the posting service and the `LiveData` report. It
creates a signing key for a new station and retains your existing settings on
an update.

Set the endpoint URL in `weewx.conf`:

``` ini
[StdRESTful]
    [[LiveData]]
        url = https://example.com/live.php
```

Restart WeeWX. The next report run generates `live.php` in your configured
`HTML_ROOT`, usually `public_html`, using the signing key in `weewx.conf`.
The FTP or rsync report uploads it with your pages. If you publish another way,
upload that generated copy yourself.

Open the endpoint URL in a browser. It should answer `POST only`. If you see PHP
source, configure the host to execute PHP before continuing.

Once LOOP packets arrive, `live.json` should appear beside
`live.php`. Your page can fetch it at `https://example.com/live.json`.

## Reading the live values

Read `live.json` with browser caching disabled:

``` js
const response = await fetch('live.json', {cache: 'no-store'});
if (!response.ok) throw new Error('Live readings: HTTP ' + response.status);
const live = await response.json();
console.log(live.current);
```

Repeat the request every ten seconds with the default `post_interval`.

`current` contains the latest value seen for each observation. Values are raw
numbers in the unit system identified by `usUnits`; your page converts and
formats them. Use `dateTime` to show the age of the readings. An observation
that has never reported or has gone stale is absent, so do not treat a missing
value as zero.

`day` contains today's minimum and maximum for the observations configured in
`extremes`.

The [live file format](https://github.com/hilman2/weewx-livedata/wiki/How-it-works#the-live-file)
describes the fields and unit-system codes.

## Options

These options go under `[StdRESTful] [[LiveData]]` in `weewx.conf`.

### url

The URL of `live.php`. Required.

### secret

The shared signing key, generated by the installer. The key itself is never
sent. To change it, edit `weewx.conf` and restart WeeWX. The next report run
regenerates `live.php`; publish the generated copy to your web host.

### post_interval

Seconds between posts. Default is `10`. Every LOOP packet updates the readings
regardless of this interval.

### extremes

Observations whose daily minimum and maximum are included in `day`. The
installer sets `outTemp, windSpeed, windGust, barometer, rain`. Set it empty to
omit daily extremes:

``` ini
extremes =
```

### data_binding

Database binding used to read daily extremes. Default is `wx_binding`.

## Removing the extension

Run `weectl extension uninstall livedata` and restart WeeWX. Generated report
files remain in `HTML_ROOT` and on your web host. Remove `live.php` and
`live.json` there when you stop publishing live readings.

## Publishing releases

Each release is a versioned ZIP with a SHA-256 digest in
[`repository.json`](repository.json). This repository publishes only `livedata`.
See [PUBLISHING.md](PUBLISHING.md) for the release steps.

## Tests

With WeeWX on the Python import path:

```
PYTHONPATH=bin:/path/to/weewx/src pytest tests/
```

The endpoint tests run `live.php` under PHP's built-in HTTP server. They require
`php` on `PATH` and are skipped if it is missing.
